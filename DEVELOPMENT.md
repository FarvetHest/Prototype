# v0.26: проверенный промежуточный этап

## Что реализовано

* `$5D4`: оригинальный tile 41 из ArtNem_Explosion1. GetArt использует индексы
  с единицы: $1F → ArtNem_Explosion1, VDP $B560, начало $5AB. Отсюда
  $5D4-$5AB=41. Сохранены 8×8 пикселей, строки 12/12/11/11 и отсутствие зеркалирования.
  Доказательство: `assets/fx-5d4-source.json`, встроенная проверка fx_selftest.
* C-исполнитель исходных обработчиков BK3, Musashi только в режиме 68000.
  Заданы явные RAM/ROM границы, лимит инструкций, безопасный возврат в неизменяемую
  область программы. Каждая диагностическая проверка получает отдельное состояние RAM.
* 32 основных ObjID $0E..$4C выполняются на ПК и MIPS. Проверено по 240 шагов
  каждого обработчика: совпадают точные fixed-point координаты, mode, animation,
  количество инструкций и максимум инструкций за вызов. Недопустимых чтений/записей нет.
* Экспортированы 54 таблицы, 1529 уникальных поз и 25 страниц 512×512 T4.
  Размер сжатого набора — 1616734 байт, распакованных страниц — 3276800 байт.
  Все страницы загружаются и проверяются при старте; в кадре нет файлового ввода
  или распаковки. Новая графика не резервирует VRAM.
* Разобраны составные банки Storm/Storm2, Jet/Rocket и RobotX, смена префиксов
  в таблице Shiva, числовые таблицы оружия. Hitbox-таблицы сохраняют исходные
  адреса и байты, включая записи, выбираемые кодом и смежные алиасы.
* T4-рендер проверен в PPSSPP: диагностические группы из четырёх врагов,
  штатный масштаб сцены, source pivots, source mapping flip, базовые палитры.
  Встроенная проверка сверяет Galsia/Donovan с прежними таблицами и все
  импортированные основные hitbox-записи непосредственно с банком программы.

## Что ещё не завершено

Обработчики пока не управляют живыми врагами уровня. В диагностике PlaySound,
GetArt, PlayRoutine, Chk_CharacterCollision и Chk_EnemyCollision заменены RTS.
Оригинальные Chk_Hit и Chk_EnemyGrab выполняются, но без полной сцены это
не проверка всех боевых переходов. Игрок, уровень и действующая боёвка остаются
на предыдущем нативном C-пути.

Нужно соединить исполнитель с RAM/физикой/контактами живых объектов, диспетчером
оружия и боссовых вспомогательных объектов, исходными захватами/контратаками,
палитрами по состояниям. У Yamato выделен изменяемый источник RAM $FFA900;
в экспорте сохранён начальный ArtUnc_YamatoA, но динамическое разрушение картинки
ещё не подключено к рендеру. Сам факт успешного чтения таблиц не означает, что
все 1529 поз уже проверены визуально в бою.

Цель — 30 FPS на PSP-3000. Замеры прежнего игрового пути не подтверждают скорость
полного состава врагов с включённым новым AI. Аппаратных измерений этой сборки нет.
Релиз v0.26 и его тег пока не созданы; `RELEASE-STATUS.json` оставлен ready=false.

## Сборка и проверки

Из каталога проекта, с имеющимися PSPSDK и локальной IDA-базой BK3:

```powershell
python -m pip install python-idb==0.8.0
python tools/recover_bk3_idb.py --idb "PATH/Bare Knuckle 3 (J) [!].idb" --out build/import
python tools/prepare_bk3_vm.py --rom build/import/bk3-recovered.bin --names build/import/bk3-idb-names.json
python tools/prepare_bk3_full.py --rom build/import/bk3-recovered.bin --names build/import/bk3-idb-names.json
python build.py --pspdev PATH/TO/pspdev
python tools/check_bk3_host.py --cc PATH/TO/tcc.exe
```

Запустить `build/EBOOT.PBP` в PPSSPP с локальным remote debugger. Рядом должны
лежать `bk3-ai.dev.bin`, `bk3-graphics.bin` и `music.wav`. Затем:

```powershell
python tools/check_bk3_runtime.py --pspdev PATH/TO/pspdev
```

Для debugger нужен websocket-client. Авторитетный отчёт этой проверки:
`test-results/bk3-runtime-tests.json`, с SHA256 проверенного EBOOT.
`test-results/bk3-host-tests.json` содержит эталон, собранный из того же C-кода.

Банк `bk3-ai.dev.bin` предназначен только для разработки: из локального образа
удалены boot/header, raw-графика игроков и звуковая программа. Перед окончательной
упаковкой нужно ограничить его состав данными рабочего AI и проверить все режимы.

## Память и зависимости

Сборка сохраняет MEMSIZE=0, CPU 333 МГц и прежние framebuffer 565.
Heap увеличен с 4 до 12 МиБ для банка программы 3 МиБ и T4-страниц 3.125 МиБ.
Временный буфер распаковки освобождается после загрузки. VRAM остаётся
1605632 байт, свободно 491520 байт. Новые RAM-данные нужно проверить на реальной PSP.

Musashi: https://github.com/kstenerud/Musashi, commit
`313ebf1bd9f4d0d93341eb5ce21fd8a119e9dbdd`. Лицензия и изменения сохранены в
`src/vendor/musashi/readme.txt` и `UPSTREAM.json`; исключены неиспользуемые FPU/MMU.
Основной код собирается с -Wall/-Wextra/-Werror. Только для сторонних файлов
отключено -Wunused-variable, возникающее при отключении других моделей CPU.
